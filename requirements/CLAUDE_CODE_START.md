# Claude Codeへの開始指示

このフォルダのREQUIREMENTS.mdを読んで、車両単独事故のSTS受付モックを実装してください。

目的は「GPT-Liveで自然な会話をし、対象事案について必須情報を収集・確認し、RPA用確定データを出し、模擬基幹への登録結果まで確認する」ことです。固定順の音声質問票を作ることではありません。

## 最優先

1. 最初のIVR相当の振り分けから同一STSセッションで対応する。
2. レッカー必要→レッカー担当への模擬転送。対象外事故→模擬有人転送。対象となる車両単独・けがなし→自然聴取→模擬RPA登録。
3. 重大なけが・危険は通常分岐より優先。相手人車なしと第三者物損なしを混同しない。
4. LLMに次の会話目的・質問の順序を任せる。コードは安全・対象適合・登録権限・最終整合を検査する。固定next_fieldキューへ戻さない。
5. 登録確定・同意は最新版のスナップショットに結び付ける。OUTCOME_UNKNOWNのジョブを自動再送しない。
6. 音声の停止・通話切断・業務処理取消を区別し、後着結果で旧データを登録しない。
7. GPT-Live APIとRealtime APIのイベントを混同しない。delegationはユーザー発話完了ではない。
8. store:falseを全サービスの保存ゼロと説明しない。実顧客データ・社外秘スクリプト原文は投入しない。
9. アプリが使うLive/BrainのAPIキーはサーバの.env。モデルID/SDKは公式を確認し、実際に使用した値を記録する。
10. 実Genesys・本番RPA・実基幹へは接続しない。新しい外部サービス・有償インフラを自動契約しない。

## 進め方

- 既存リポジトリがあれば初めに構成・既存テスト・再利用できるコードを確認し、変更範囲を短く説明する。存在しないコードをレビュー済みにしない。
- 既存の比較用Deterministicモードは削除せず、新しいstrategyまたはブランチで実装する。
- 新規ならReact/TypeScript/Vite + Node/TypeScriptを基本に、単一端末モックとして最小構成にする。
- README、docs/requirements.md、docs/decisions.md、.env.exampleを先に用意する。
- APIキー未設定ならsecretを要求/表示せず、起動手順と必要な変数だけ提示する。APIテストは未実施と記録し、Mock部分は進める。
- 実キーがローカル環境に設定され、利用者が実行を開始した場合にだけAPIを呼ぶ。検証に上限時間・上限回数を設定する。
- まず実APIの小さな接続スパイク、次に文字入力から模擬RPA結果までの縦の処理、次に音声と接続、最後に失敗系評価の順で進める。
- 追加の一般設計案の提示だけで止まらず、既知条件で実装可能な部分を進める。社内規程・既存RPA項目は未確認のまま捏造しない。

## 画面

通話操作、会話、対象判定、根拠付き受付データ、会話目的、RPA登録状況を表示する。JSONはDebugに格納し、顧客向け音声へ流さない。

## 完了時の提出

1. 起動・停止方法と必要環境変数（秘密値は含めない）。
2. 変更/追加ファイルと再利用した既存機能。
3. 通常の車両単独事故、レッカー、第三者物損、訂正、RPA結果不明の各動作記録。
4. 実API/模擬API/未検証の区別。
5. lint/typecheck/unit/integration/buildの実行結果と未実施項目。
6. acceptance-cases.jsonに対する合否・根拠ログ。自動判定だけでなく重要な音声内容を人が確認する方法。
7. 実Genesys/RPA連携前に必要な確認事項。

同梱のJSONはアプリ独自のサンプル/テスト定義です。既存RPAやOpenAIの正式API仕様と見なさないでください。
